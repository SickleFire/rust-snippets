tokio-runtime

1. The Runtime Engine

Because Rust does not feature a built-in asynchronous runtime in its standard library, an external executor is required to drive async code and .await expressions to completion.

Key Concepts

  • The Multi-Threaded Work-Stealing Executor: #[tokio::main] bootstraps a multi-threaded Tokio runtime that manages worker threads across CPU cores.
  • Non-Blocking I/O: Instead of blocking OS threads when waiting for disk or network operations, Tokio parks the task and switches execution to ready work.
  • Async / Await Model: Futures are lazy in Rust; they do nothing until polled or awaited on the runtime.

Code Pattern

#[tokio::main]
async fn main() {
    // Bootstrap the Tokio runtime and await async work
    async_hello().await;
}

async fn async_hello() {
    println!("Hello from an asynchronous function driven by Tokio!");
}
tokio::spawn

2. Spawning Tasks (`tokio::spawn`)

Submitting background tasks concurrently without blocking the main flow of execution using lightweight green tasks.

Key Concepts

  • Green Tasks vs OS Threads: tokio::spawn creates a lightweight task managed inside the Tokio worker pool rather than spawning heavy OS threads.
  • Lifetime & Send Bounds: Tasks spawned with tokio::spawn must own their data or have a `'static` lifetime and implement Send.
  • JoinHandle: A future representing task completion. Awaiting the handle yields the return value of the spawned task.

Code Pattern

#[tokio::main]
async fn main() {
    // Spawn a background task
    let handle = tokio::spawn(async {
        println!("Background task started...");
        tokio::time::sleep(tokio::time::Duration::from_millis(100)).await;
        "Task completed!"
    });

    // Await task completion and retrieve result
    let result = handle.await.unwrap();
    println!("Main received: {result}");
}
tokio::time

3. Asynchronous Timers (`tokio::time`)

Managing timeouts, delays, and scheduling in asynchronous workflows without freezing runtime worker threads.

Key Concepts

  • Never Use Blocking Sleep: std::thread::sleep blocks the underlying OS thread, freezing the Tokio worker. Always use tokio::time::sleep.
  • Async Sleep: Suspends the current task asynchronously for the specified duration, yielding the worker thread to other ready tasks.
  • Timeouts: Wrap any future with tokio::time::timeout to enforce strict time bounds on async operations.

Code Pattern

use tokio::time::{sleep, timeout, Duration};

async fn slow_operation() -> &'static str {
    sleep(Duration::from_millis(200)).await;
    "Success"
}

#[tokio::main]
async fn main() {
    // Enforce a timeout of 100ms on a 200ms operation
    let res = timeout(Duration::from_millis(100), slow_operation()).await;
    
    match res {
        Ok(val) => println!("Operation finished: {val}"),
        Err(_) => println!("Operation timed out!"),
    }
}
tokio::sync

4. Task Synchronization & Channels (`tokio::sync`)

Communicating safely between concurrent asynchronous tasks without shared mutable state.

Key Concepts

  • MPSC Channel (tokio::sync::mpsc): Multi-producer, single-consumer channel enabling multiple tasks to stream messages to a single receiver.
  • Oneshot Channel (tokio::sync::oneshot): Transfers a single value from one sender to one receiver, ideal for request-response patterns.
  • Channel Closing: Dropping all transmitter handles causes rx.recv() to return None, terminating message loops cleanly.

Code Pattern

use tokio::sync::mpsc;

#[tokio::main]
async fn main() {
    let (tx, mut rx) = mpsc::channel(32);

    let tx_clone = tx.clone();
    tokio::spawn(async move {
        tx_clone.send("Hello from producer").await.unwrap();
    });

    drop(tx);

    while let Some(msg) = rx.recv().await {
        println!("Received: {msg}");
    }
}
tokio::join

5. Joining Multiple Futures (`tokio::join!`)

Running multiple independent asynchronous operations concurrently on the current task and combining their results.

Key Concepts

  • Concurrent Execution: tokio::join! polls multiple futures concurrently on the same task without needing separate spawns.
  • Tuple Return Value: Returns a tuple containing the resolved output of each future once all of them complete.
  • All-Or-None Completion: Execution blocks on the join! macro until every provided future has resolved.

Code Pattern

async fn fetch_user() -> &'static str {
    "Alice"
}

async fn fetch_score() -> u32 {
    42
}

#[tokio::main]
async fn main() {
    // Run both futures concurrently and retrieve both results
    let (user, score) = tokio::join!(fetch_user(), fetch_score());
    
    println!("User: {user}, Score: {score}");
}
reqwest::Client

1. The HTTP Client (`reqwest::Client`)

The entry point for making HTTP requests. Reusing a Client instance pools connections automatically for maximum performance.

Key Concepts

  • Connection Pooling: A single Client maintains internal connection pools (keep-alive), avoiding TCP handshake overhead on repeated requests.
  • Configuration: Use ClientBuilder to set global timeouts, default headers, proxies, and redirect policies.
  • Thread-Safe & Cheap to Clone: Client is internally reference-counted (Arc-backed) and can be freely cloned and shared across async tasks.

Code Pattern

use reqwest::Client;

#[tokio::main]
async fn main() -> Result<(), reqwest::Error> {
    // Create a shared HTTP client
    let client = Client::new();

    let res = client.get("https://httpbin.org/get").send().await?;
    println!("Status: {}", res.status());

    Ok(())
}
reqwest::get

2. Simple GET Requests

Fetching data from an HTTP endpoint using straightforward asynchronous GET methods for quick scripts or simple queries.

Key Concepts

  • Convenience Function: reqwest::get() is a shorthand for quick one-off GET requests without creating a custom Client.
  • Response Handling: The Response object contains status code, headers, and methods to consume the body as text, bytes, or JSON.
  • Error Propagation: Network failures, DNS errors, or HTTP errors return a reqwest::Error which can be handled with the ? operator.

Code Pattern

#[tokio::main]
async fn main() -> Result<(), reqwest::Error> {
    // Perform a simple GET request
    let body = reqwest::get("https://httpbin.org/ip")
        .await?
        .text()
        .await?;

    println!("Response Body:\n{body}");
    Ok(())
}
reqwest::json

3. JSON Deserialization

Automatically parsing JSON HTTP response bodies directly into strongly-typed Rust structs using Serde integration.

Key Concepts

  • .json::().await: Consumes the response body and deserializes it directly into any type T that implements serde::Deserialize.
  • Type Safety: Replaces fragile dynamic JSON maps with robust, compile-time checked Rust structs.
  • Content-Type Validation: Reqwest automatically reads and handles JSON response text streams.

Code Pattern

use serde::Deserialize;

#[derive(Deserialize, Debug)]
struct Todo {
    userId: u32,
    id: u32,
    title: String,
    completed: bool,
}

#[tokio::main]
async fn main() -> Result<(), reqwest::Error> {
    let todo: Todo = reqwest::get("https://jsonplaceholder.typicode.com/todos/1")
        .await?
        .json()
        .await?;

    println!("Fetched Todo: {todo:?}");
    Ok(())
}
reqwest::post

4. POST Requests & JSON Payloads

Sending data to remote APIs by attaching request bodies, custom headers, and query parameters.

Key Concepts

  • .json(&body): Serializes any serializable Rust struct into JSON and automatically sets the Content-Type: application/json header.
  • Query Parameters: Use .query(&[("key", "val")]) to append URL search parameters cleanly.
  • Custom Headers: Use .header("Authorization", "Bearer token") to attach authentication tokens.

Code Pattern

use serde::{Serialize, Deserialize};
use reqwest::Client;

#[derive(Serialize)]
struct NewPost {
    title: String,
    body: String,
    userId: u32,
}

#[derive(Deserialize, Debug)]
struct PostResponse {
    id: u32,
}

#[tokio::main]
async fn main() -> Result<(), reqwest::Error> {
    let client = Client::new();
    let payload = NewPost {
        title: "Reqwest in Rust".into(),
        body: "Bite-sized async HTTP lessons.".into(),
        userId: 1,
    };

    let res = client.post("https://jsonplaceholder.typicode.com/posts")
        .json(&payload)
        .send()
        .await?
        .json::()
        .await?;

    println!("Created post with ID: {}", res.id);
    Ok(())
}
serde::derive

1. Deriving `Serialize` & `Deserialize`

Enabling automated conversion between Rust structs/enums and data formats like JSON using procedural macro derives.

Key Concepts

  • #[derive(Serialize, Deserialize)]: Automatically generates serialization and deserialization logic at compile time without manual boilerplate.
  • Zero-Cost Abstraction: Serde generates optimized parsing code tailored to your struct layouts with minimal overhead.
  • Standard Formats: Data structures derived with Serde can be serialized into JSON, TOML, YAML, MessagePack, and dozens of other formats.

Code Pattern

use serde::{Serialize, Deserialize};

#[derive(Serialize, Deserialize, Debug)]
struct User {
    username: String,
    age: u8,
    active: bool,
}

fn main() {
    let user = User { username: "Alice".into(), age: 30, active: true };
    
    // Serialize to JSON string
    let json = serde_json::to_string(&user).unwrap();
    println!("JSON: {json}");

    // Deserialize back to User struct
    let parsed: User = serde_json::from_str(&json).unwrap();
    println!("Parsed: {parsed:?}");
}
serde::rename

2. Field Renaming & Aliases

Handling API payloads whose naming conventions differ from standard Rust idioms (e.g. snake_case vs camelCase).

Key Concepts

  • #[serde(rename = "...")]: Renames an individual struct field to match external JSON property names.
  • #[serde(rename_all = "...")]: Automatically applies naming transformations ("camelCase", "PascalCase", "kebab-case") to all fields in a struct.
  • Keyword Escaping: Allows mapping external keys that clash with Rust reserved keywords (like type or async).

Code Pattern

use serde::{Serialize, Deserialize};

#[derive(Serialize, Deserialize, Debug)]
#[serde(rename_all = "camelCase")]
struct UserProfile {
    user_id: u64,
    first_name: String,
    // Manually override a specific field name
    #[serde(rename = "emailAddress")]
    email: String,
}

fn main() {
    let json = r#"{"userId": 42, "firstName": "Bob", "emailAddress": "bob@example.com"}"#;
    let profile: UserProfile = serde_json::from_str(json).unwrap();
    println!("{profile:?}");
}
serde::default

3. Optional Fields & Defaults

Gracefully handling missing JSON keys, optional properties, and fallback default values during deserialization.

Key Concepts

  • Option<T>: Deserializes missing or null JSON fields as None instead of returning a parsing error.
  • #[serde(default)]: Populates missing fields using the type's implementation of Default::default().
  • Custom Default Functions: Use #[serde(default = "function_name")] to specify custom fallback values.

Code Pattern

use serde::{Serialize, Deserialize};

fn default_role() -> String {
    "guest".to_string()
}

#[derive(Deserialize, Debug)]
struct Settings {
    theme: Option<String>,
    #[serde(default = "default_role")]
    role: String,
    #[serde(default)]
    notifications: bool,
}

fn main() {
    let json = r#"{}"#; // Empty JSON object
    let settings: Settings = serde_json::from_str(json).unwrap();
    println!("{settings:?}"); // role: "guest", notifications: false, theme: None
}
serde::flatten

4. Flattening & Custom Serialization

Merging nested JSON structures or handling dynamic attributes without losing type safety.

Key Concepts

  • #[serde(flatten)]: Merges fields from a nested struct or extra HashMap directly into the parent JSON object level.
  • #[serde(skip)]: Ignores specific fields during serialization and/or deserialization.
  • Custom Converters: Use #[serde(with = "module")] for custom serialization logic on specific fields (e.g. timestamps).

Code Pattern

use serde::{Serialize, Deserialize};
use std::collections::HashMap;

#[derive(Deserialize, Debug)]
struct Event {
    id: String,
    // Flatten remaining dynamic properties into a HashMap
    #[serde(flatten)]
    extra: HashMap<String, serde_json::Value>,
}

fn main() {
    let json = r#"{"id": "ev_123", "action": "click", "count": 5}"#;
    let event: Event = serde_json::from_str(json).unwrap();
    println!("{event:?}");
}
